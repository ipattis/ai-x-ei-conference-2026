Context

What does "edge AI" actually mean?

Cloud AI (what you're used to)

Your prompt travels to a data centre (OpenAI, Google, Microsoft). A huge model runs on GPU clusters. A response comes back. Your data touched someone else's system.

Edge AI (what's now possible)

The model is the browser tab. Your prompt runs on your own hardware — CPU or GPU — using WebAssembly or WebGPU. Nothing leaves the device. Ever.

Why now?

  • 1Quantisation: 4-bit models are 4–8× smaller with minimal quality loss
  • 2WebGPU: browser-native GPU access, no install required
  • 3Open weights: Gemma, Qwen, Llama, Phi — free to download and run
  • 4Transformers.js: HuggingFace's library brings the full pipeline to JS

Pillar 2 — System Prompting

You define the AI's identity

A system prompt is the instruction that runs before any student interaction. It shapes everything: tone, vocabulary level, what topics to avoid, what role to play.

Example: Year 6 Reading Companion

// System prompt for a primary reading assistant "You are Archie, a friendly reading buddy for Year 6 pupils aged 10–11. Always use simple vocabulary. Never give away plot answers — instead ask the pupil what THEY think happens next. If a pupil seems stuck, offer encouragement first. Keep responses under 4 sentences."

Example: Teacher CPD Planner

"You are a coaching assistant for teachers preparing CPD sessions. Ask clarifying questions before making suggestions. Ground all advice in the DfE Teachers' Standards. Avoid educational jargon."

What a system prompt controls

  • 🎭Persona — name, role, personality
  • 📏Reading level — GCSE, KS2, adult
  • 🚫Topic boundaries — what to refuse or redirect
  • 💬Response style — Socratic, direct, encouraging
  • 🌍Values — your school's ethos, safeguarding tone
  • 📝Format — bullet points, short answers, markdown

No developer needed. A teacher who knows their learners writes better system prompts than any product manager at a tech company ever will.

Pillar 3 — Knowledge Base / RAG

The AI knows what you teach it

RAG — Retrieval Augmented Generation — means the AI searches your uploaded documents before answering, then grounds its response in what it finds.

How it works (locally, in the browser)

  1. 1You upload a .txt document — curriculum spec, policy, marking guide
  2. 2It's split into chunks (~500 chars each) and converted to dense vector embeddings
  3. 3Stored in IndexedDB — stays on the device, survives page reloads
  4. 4When a pupil asks something, the most relevant chunks are retrieved
  5. 5Those chunks are injected into the model's context before it replies

What to upload

AQA Spec School Marking Policy Reading List SEN Guidelines Lesson Plans School Handbook CPD Notes Safeguarding Policy

Hybrid scoring — smarter retrieval

Combines semantic similarity (meaning) with keyword matching (exact terms) — 70/30 blend — so "What does the spec say about quadratics?" finds the right chunk even if it doesn't use the word "spec".

All vectors stored in the browser's IndexedDB. No cloud. No third party. No data protection headache.

import { pipeline } from '@huggingface/transformers'; // Point to public model CDN — or your own env.remoteHost = "https://cdn.thinkhere.ai/"; // Load quantised model (4-bit = ~1.2GB) const model = await Gemma4ForConditionalGeneration .from_pretrained("onnx-community/gemma-4-E2B-it-ONNX", { dtype: "q4f16", device: "webgpu", // GPU in the browser });

Injecting the system prompt

const messages = [ { role: "user", content: [{ type: "text", text: /* system prompt */ + "\n\n" + userMessage }]} ]; // Gemma prepends system to first user turn const prompt = processor.apply_chat_template( messages, { add_generation_prompt: true } );

RAG: retrieve relevant chunks

// Hybrid: 70% semantic + 30% keyword const scored = allChunks.map(chunk => { const semantic = cosineSimilarity( queryEmbedding, chunk.embedding ); const keyword = keywordScore(query, chunk.text); return { ...chunk, score: 0.7 * semantic + 0.3 * keyword }; }); const context = scored .filter(c => c.score >= 0.15) .sort((a,b) => b.score - a.score) .slice(0, 3000 /* chars */);

Safeguarding & Data Protection

What happens to student data?

With this approach

  • ✅All inference happens on the device — zero network requests
  • ✅Conversation history stored in browser's IndexedDB — local only
  • ✅Knowledge base docs stored locally as embeddings
  • ✅No account required — no identity linkage
  • ✅GDPR friendly by design — no processor agreement needed
  • ✅Works on an air-gapped school network

What Big Tech tools require

  • ⚠️Student data processed on third-party servers
  • ⚠️Data retention and training policies vary — and change
  • ⚠️US-based cloud = Schrems II / international transfer risk
  • ⚠️Age-verification obligations for under-13s
  • ⚠️DPA / data processor agreement required
"The most compliant AI tool is one where the data never leaves the building."
